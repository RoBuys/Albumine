# Albumine

A photo manager for macOS (SwiftUI) in the spirit of the classic "local" organizers such as Picasa:
your photos stay in your own folders — nothing is moved, nothing is modified, and all analysis
runs on your Mac.

Tested on a 190,000-item library (photos and videos) on an external drive.

> **Language:** the user interface is in French. Menu and button names below are quoted as they
> appear in the app, with an English translation.

## Install

**Download:** grab `Albumine-1.0.zip` from the [latest release](https://github.com/RoBuys/Albumine/releases/latest),
unzip it and drag **Albumine.app** into **Applications**. The app is not signed with an Apple
Developer ID, so on first launch macOS blocks it: right-click the app › **Open** › **Open**
(or System Settings › Privacy & Security › **Open Anyway**). This is needed only once.

**Build from source** (no Gatekeeper warning): requires macOS 14 or later and Apple's Command
Line Tools — Xcode is not required.

```bash
xcode-select --install          # once, if the tools are not installed yet
git clone https://github.com/RoBuys/Albumine.git
cd Albumine && ./build.sh && cp -R Albumine.app /Applications/
```

The icon is generated by `Resources/make-icon.swift` (run `swift Resources/make-icon.swift` again after changing it).

## Updates

From version 1.1, Albumine updates itself: at launch (at most once a day) and via
Albumine › "Rechercher les mises à jour…" (Check for updates), it reads the latest
[GitHub release](https://github.com/RoBuys/Albumine/releases). When a newer version exists it
shows the release notes and offers "Installer et relancer" (Install and relaunch).

Every update archive is signed with the author's Ed25519 key; the app embeds the public key and
refuses any archive whose signature does not match — even one served by GitHub. It also checks the
bundle identifier, version and code signature before swapping the app and relaunching it. Your data
(`~/Library/Application Support/Albumine`) is never touched. Automatic checks can be turned off in
Settings › Options.

### Publishing a release (maintainer)

```bash
./release.sh 1.1 notes.md
```

Sets the version, builds, zips and signs the archive, commits, tags `v1.1`, pushes and creates the
GitHub release with `Albumine-1.1.zip` and `Albumine-1.1.zip.sig`. The signing key lives in the
login Keychain ("Albumine update signing key", see `Resources/update-key.swift`); **back it up** —
without it, installed copies cannot be updated automatically anymore.

## Features

- **Folders**: add (⌘O, toolbar button, drag and drop), recursive scan, rescan (⌘R);
  **Settings (⌘,) › Dossiers** (Folders): list of scanned folders (item count, drive connected or not),
  add, remove, **exclude subfolders** (also via right-click on a folder)
- **Grid**: fast thumbnails (adjustable size), **grouping by folder, month, year or event**
  (pinned headers, "Tout sélectionner" / Select all), sort by capture date or name
- **Videos** (MOV, MP4, M4V, 3GP…; AVI/WMV are listed and opened in the default app):
  thumbnail, playback in the viewer, date and location read from metadata
- **Viewer**: double-click or Return/Space; ← →; F shows face frames; E opens the editor; Esc closes
- **Ratings** 0–5 stars (keys 0–5), **tags**, **captions**, display **rotation**
- **Virtual albums**: a photo can be in several albums without being copied; create (+), drag photos
  onto an album, right-click › "Ajouter à l'album" (Add to album), rename, delete (photos are kept)
- **People / faces**: detection and recognition with Apple's Vision framework (on-device, nothing is
  uploaded). Already named faces serve as examples; new faces get a *suggested* name to confirm in
  "Visages à nommer" (Faces to name) or in the inspector
- **People management**: rename, merge (likely duplicates detected: case, accents, first name only),
  hide, profile picture (portrait in the sidebar) — Settings › Personnes (People) or right-click
- **Content search**: "plage" (beach), "neige" (snow), "chien" (dog)… — 1,300 categories recognized by
  Vision, translated into French; background analysis that can be paused
- **Text in photos** (Vision OCR): signs, documents, screenshots become searchable
- **Places**: city and country names from GPS (Apple geocoding, one ~2 km area at a time),
  "Lieux" (Places) sidebar section, search by place
- **Locations for photos without GPS**: right-click › Lieu › "Définir le lieu…" (Set location: map and
  address search) or "from photos taken just before or after" (≤ 2 h apart)
- **Map**: geotagged photos clustered by zoom level; click a cluster for a photo strip, double-click to view
- **Automatic events**: "Par événement" grouping (new event after a 6 h gap, or 1 h and 40 km),
  titled with the most frequent place
- **Memories**: "On this day, N years ago" banner, dedicated view, slideshow
- **Timeline** on the edge of the grid and a **period filter** (from / until a given year)
- **Combined search with suggestions**: e.g. "Sacha plage 2012"; people, places, albums, tags,
  content and years are suggested while typing
- **Search** covers file name, folder, person, album, tag, caption, content, text, place, camera,
  year (accent-insensitive)
- **Non-destructive editing** (viewer, key E): "J'ai de la chance" (auto-enhance), exposure, contrast,
  highlights, shadows, saturation, warmth, filters (black and white, sepia…), straighten, crop
  (free, square, 4:3, 3:2, 16:9…); applied to display, slideshow and export
- **Batch date correction** (right-click › "Corriger la date…"): shift dates (wrong camera clock) or set
  an exact date (scanned photos), with preview; original dates can be restored
- **Exact duplicates**: same size + fingerprint, then byte-by-byte comparison before removal; the most
  annotated copy is kept, the others go **to the Trash** (recoverable) and their ratings, people and
  albums are carried over
- **Similar photos**: bursts and resized versions (perceptual hash + time proximity);
  "keep the best of each series" (best according to Vision and your annotations)
- **Failed photos**: blurry, too dark, overexposed, screenshots and documents, poor shots;
  "Ce n'est pas raté" (Not a failure) removes a photo from the list
- **Slideshow**: full screen, crossfade, slow zoom, optional music (Space, ← →, Esc)
- **Export** (size, quality, rotation and edits, GPS removal) and **Share** (Mail, Messages, AirDrop…)
- **XMP sidecars**: import existing sidecars (Mylio, Lightroom, digiKam: ratings, people and face
  regions, captions, locations); optional writing of your annotations (Bibliothèque / Library menu,
  off by default), **merged** into the existing XMP without losing other applications' data
- **Disconnected drive**: the library stays browsable (index + cached thumbnails); reconnection is
  detected automatically. **Folder watching**: new photos are picked up on their own
- **Backup** (Settings › Sauvegarde): incremental copy to another drive (folder structure preserved,
  only missing or changed files, never deletes anything, atomic copies) + Albumine's own data
- **Integrity check**: detects empty, truncated or unreadable files ("Fichiers abîmés" / Damaged files view)
- **Inspector**: EXIF (date, dimensions, camera, lens, settings, GPS → Maps), recognized content and
  text, faces, people, albums
- **Large libraries**: instant listing, metadata read in the background, persistent index, on-disk
  thumbnail cache, throttled disk reads to keep the grid smooth

## Picasa import

File › **"Importer depuis Picasa…"** (Import from Picasa), or the banner shown when `.picasa.ini`
files are detected. Reads the `.picasa.ini` / `Picasa.ini` file of each folder and imports, without
modifying any file:

| Picasa | Albumine |
|---|---|
| named faces (`faces=` + `[Contacts2]`) | **People** (sidebar, search); face regions kept |
| albums (`albums=` + `[.album:…]`) | **Albums** |
| `rotate=rotate(n)` | display rotation |
| `star=yes` | 5 stars |
| `caption=` | caption |
| `filters=` (enhance, B&W, sepia, warm…) | equivalent non-destructive edits |

The import only adds information, so it can safely be run again. Picasa stores face regions in the
raw image orientation (before EXIF rotation); Albumine converts them. Hidden `Originals` folders
(pre-edit copies kept by Picasa) are skipped on purpose.

## Data

- `~/Library/Application Support/Albumine/library.json`: scanned folders, exclusions, ratings, tags, people, albums, edits…
- `~/Library/Application Support/Albumine/index.json`: file index and EXIF metadata
- `~/Library/Application Support/Albumine/faceprints.dat`: face fingerprints of the example faces
- `~/Library/Application Support/Albumine/analysis.json`: content analysis (categories, quality, text, fingerprints)
- `~/Library/Application Support/Albumine/places.json`: place names
- `~/Library/Application Support/Albumine/xmp-state.json`: last state written to each XMP sidecar
- `~/Library/Caches/Albumine/Miniatures`: thumbnails (safe to delete)

Environment variables useful for development: `ALBUMINE_HOME` (alternate data folder),
`ALBUMINE_DEBUG` (log to stderr), `ALBUMINE_AUTOIMPORT` (automatic Picasa import at launch),
`ALBUMINE_START_VIEW=map` (open the map view at launch).

## Technical note

The Command Line Tools SDK declares `@State` as a macro but does not ship its compiler plugin, so the
code uses the alias `@Etat` (= `SwiftUI.State`). With Xcode, `@State` works as well.
